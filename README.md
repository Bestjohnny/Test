# Test 仓库新手指南

## 1. 仓库整体结构

当前仓库是一个**初始化后的空仓库骨架**，尚未包含业务代码或配置。

- `.git/`：Git 元数据目录，用于版本历史、分支、索引等信息。
- `.gitkeep`：占位文件（空文件），通常用于保证空目录或最小仓库状态可被提交。

## 2. 目前需要优先了解的关键内容

由于代码尚未落地，建议先从“工程规范”而不是“业务逻辑”入手：

1. **分支与提交流程**：
   - 当前分支：`work`
   - 当前历史仅有初始化提交。
2. **项目初始化规划**：
   - 技术栈（语言、框架、包管理器）
   - 目录分层（如 `src/`、`tests/`、`docs/`）
   - 代码风格与格式化工具（如 lint/format）
3. **最小可运行目标（MVP）**：
   - 先定义“能跑起来”的最小版本，再补充测试、CI、部署。

## 3. 新人后续学习建议（按优先级）

1. **先建立工程骨架**
   - 增加 README 的“启动步骤”和“开发规范”。
   - 落地基础目录结构与示例模块。

2. **同步团队协作约定**
   - 提交信息规范（例如 Conventional Commits）。
   - PR 模板、代码评审清单。

3. **补齐质量保障**
   - 添加最小单元测试。
   - 配置 CI（至少包含安装依赖 + 测试 + lint）。

4. **沉淀文档资产**
   - 新增 `docs/architecture.md`（架构图与边界说明）。
   - 新增 `docs/onboarding.md`（环境搭建、FAQ、常见坑）。
